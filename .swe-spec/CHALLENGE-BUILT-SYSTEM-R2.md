## 2. CONFIRMED defects, BLOCKER → MINOR

### BLOCKER (9)

1. **`structural-ci-diff.mjs` CI-block gate bypassed by whitespace/newline-padded `impact`** — `scripts/core/structural-severity.mjs` `canonicalImpact()`. Repro: `impact:"CRITICAL"` → blocks (exit 1); `impact:"critical\n"` → clean pass (exit 0). `canonicalImpact()` lowercases but never trims. `structural-ci-diff.mjs` (the documented standalone CI-merge gate) never calls the fail-closed `isValidImpact()` that a sibling gate has. **Fix:** trim before lowercasing in `canonicalImpact()`/`isValidImpact()`; make `structural-ci-diff.mjs` call `isValidImpact()` and fail closed.

2. **Findings with no `target_element_identifier` skip route grounding AND can be falsely merged across personas** — `assemble-run.mjs` `grounded()`/`clusterKey()` fallback. Repro: two personas, no `target_element_identifier`, same `heuristic_tag`+`step`, one narrative self-admits it references a page never visited → both merge into one `convergence_tier: 2` finding, fabricated finding wins as representative, no drop logged. **Fix:** scope the fallback cluster key per-persona (no cross-persona merge without a shared element identifier); require `target_element_identifier` at ledger-ingestion or drop tei-less findings as ungrounded.

3. **Trace-grounding fails open when `trace.json` is entirely absent** — `assemble-run.mjs` line ~64: `if (!tr || !Array.isArray(tr.steps)) return true; // cannot disprove (kept)`. Repro: 3 personas, no `trace.json`, fabricated finding (step 999, invented page) → survives clustering at `convergence_tier: 3`, ships `report-gate: PASS`, exit 0. **Fix:** flip to fail-closed — missing trace ⇒ drop with `DROPPED-UNGROUNDED ... no trace.json present`.

4. **Missing `target_element_identifier` disables the B4/B5 route-grounding check entirely** — same `grounded()`, `pageOf()` returns `null` on absent tei, skipping the whole route-check block. Repro: annotated ledgers correctly drop 5 off-route findings; identical findings with tei stripped → 0 drops, fabricated pricing-page findings ship. **Fix:** ground every finding against its own cited step's actual trace URL, independent of whether tei carries a page prefix.

5. **Same fail-open-on-no-trace defect, reproduced full end-to-end through `report-gate.mjs`** — confirms the BLOCKER above is not merely a unit-level gap: fabricated finding with forged `evidence` + valid heuristic passes `report-gate: PASS`, exit 0, no BLOCKED/floor state catches it. **Fix:** same as item 3, plus ensure trace-less personas are reflected as non-"completed" in `run_status` so `deriveBlocked()` can catch the aggregate case.

6. **`report-gate.mjs` silently passes a critical structural (WCAG) bundle when `lane` is merely omitted** — `if (bundle.lane === 'structural')` is an exact-match allowlist, not fail-closed. Repro: real axe:label critical finding, `lane:'structural'` present → correctly refused (exit 1); same bundle with `lane` deleted → zero-evidence drop masks it, `gate: PASS`, exit 0. Sibling gates (`structural-report-gate.mjs`, `structural-ci-diff.mjs`) both fail closed on non-`'structural'` (including absent); this one doesn't. **Fix:** detect structural *shape* (violation_ids/axe: finding codes/axe metadata) independent of the literal lane string and refuse if shape says structural but lane doesn't confirm persona.

7. **`assemble-run.mjs` `clusterKey()` drops `heuristic_tag` from its dominant (tei-present) branch, causing real over-merge** — contradicts the function's own header comment (which quotes the F45 3-tuple including `heuristic_tag`) and its sibling `core/identity.mjs`, which does include it. Repro: sev-1 contrast finding + unrelated sev-4 redirect-to-paywall finding, same step/tei, different tag → collapse into ONE finding, `convergence_tier` falsely reported as 2, the sev-1 finding vanishes except as a buried voice-note. Ships `report-gate: PASS` because the gate only re-checks the already-collapsed output. **Fix:** include `heuristic_tag` in the tei branch's key (or delegate to `core/identity.mjs`'s `tupleKey()` directly).

8. **Trace grounding's hardcoded 6-route `PAGE_PATH` allowlist drops genuine, actually-visited findings and mislabels them "likely fabricated"** — `PAGE_PATH` recognizes only `{landing,nav,signup,verify,dashboard,pricing}`, matched against the demo fixture app only. Repro: finding on a genuinely-visited `/settings` page (trace.json proves the visit) → dropped as `"likely fabricated"`, `run_status` forced BLOCKED. Worse: the spec's own canonical tier-1 identifier format (`data-testid:cta-signup`) is misparsed by the same regex and also dropped. No spec text restricts the tool to the demo app; this defeats grounding for any real target site. Undisclosed anywhere (grep of specs/commit notes for `PAGE_PATH` = zero hits outside source). **Fix:** derive grounding from the persona's own visited-URL set in its trace, not a static name→path table; never label a drop "fabricated" when the real cause is "not in a maintained allowlist."

9. **Duplicate confirmation of #8 via a distinct repro angle (honesty-audit lens)** — same root cause, same fix. Retained as a separate finding because it was independently reproduced through a different fixture and demonstrates the defect is not an artifact of one specific repro.

## 4. Persona-LLM residual verdict: real blocker or acceptably disclosed?

**Verdict: real blocker for real runs, only partially disclosed, and the undisclosed part is the dangerous part.**

The core fact, confirmed by direct grep, not inference: `target_element_identifier` has **zero algorithmic backing in the persona lane**. `crawl.mjs` emits no selector/testid data into `trace.json` (`grep -c target_element_identifier scripts/crawl.mjs` = 0), and the priority-ordered stable-identifier algorithm the specs cite (F103/F183/F193) is implemented only in `core/structural-identity.mjs`, scoped explicitly to the structural (axe/DOM) lane. On a real run, this field is 100% free-form text from an LLM persona subagent with no shared naming convention across personas.

That single fact fans out into every persona-lane defect in this report:
- **Disclosed, at spec level:** the under-merge failure mode (item 19) is named in spec F104 with a stated mechanism and an operator workaround (match on step+tei, not `finding_id`), and a full fix is an explicit deferred non-goal. This is honest, if buried.
- **NOT disclosed anywhere:** the grounding-bypass failure modes are undisclosed in both spec and commit notes. Grepping specs and `.swe-spec/*.md` for `PAGE_PATH` returns nothing outside the source line itself (item 8/9). The fact that an absent tei disables the entire B4/B5 route check (item 4) is not named as a residual anywhere. The fact that the internal cluster key leaks into the public tei field, corrupting the documented cross-lane join contract (item 16), is not named. These are not "known limitations" — they are silent correctness failures in the exact mechanism (trace-grounding) the tool's core pitch depends on ("findings are trace-grounded, off-trace dropped").
- **The live suite doesn't test the realistic case at all:** the one test built to prove grounding works on real personas hand-authors an idealized `target_element_identifier` (item 17) — the same fixture-theater failure class the live suite was supposedly built to eliminate, now relocated to the new suite.

So: acceptable disclosure exists for one specific, narrow sub-case (under-merge via naming divergence). It does not exist for the more severe sub-cases (grounding bypass, false convergence, field corruption), all of which are reachable on a normal, non-adversarial real run — an LLM persona simply omitting or freely wording `target_element_identifier`, which is the default expectation, not an edge case. Calling the residual "disclosed" for the system as a whole overstates the actual disclosure surface.
