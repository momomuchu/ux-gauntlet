F1: The skill MUST load each persona from a structured data file that conforms to the persona schema.

F9: At each executed task step the persona agent MUST record an answer to each of the 4 cognitive-walkthrough questions before advancing. # CR4-M1
F10: The persona agent MUST record one friction instance for every action performed beyond the happy-path task list.
F11: Each friction instance MUST carry exactly one criterion tag drawn from the configured heuristic set.
F12: Each friction instance's severity score MUST equal round(mean(frequency, impact, persistence)), each of the 3 rubric factors scored 0-4 whenever severity_factors is stored as 3 numeric values; when severity_factors is stored as free-text rationale, the recorded severity value is authoritative. # CR1-16 CR2-20
F13: Each friction instance MUST carry a market-impact flag that is stored separately from the severity score.
F14: Each friction instance MUST reference at least one captured evidence artifact.
F15: The report generator MUST drop every finding that references zero evidence artifacts.
F16: A standard audit run MUST execute at least 3 personas against the same task list.
F17: The report MUST assign each finding a convergence tier equal to the integer count of run_status-completed personas that flagged it. # CR1-18
F18: The primary run output MUST be a JSON findings file that validates against the findings schema.
F19: The markdown report MUST be generated from the JSON findings file.
F20: Every generated report MUST contain the validity-envelope disclosure section.
F21: The report generator MUST NOT emit willingness-to-pay estimates.
F22: The report generator MUST NOT emit population-percentage extrapolations.
F23: The report gate script MUST exit nonzero when the JSON findings file violates the findings schema.
F24: The report gate script MUST exit nonzero when any finding lacks a tag from the configured heuristic set. # CR4-M5 CR4-MIN5
F25: The persona validator script MUST exit nonzero when a persona file violates the persona schema.
F26: CI mode MUST exit nonzero when the run produces a severity-4 finding absent from the committed baseline. # CR1-2 CR1-19 CR2-22
F27: The report MUST label findings from operator-allowlisted standardized flows as lower-confidence.
F28: The heuristic set MUST load from a data file, with the Nielsen 10-heuristic list shipped as the default set.
F29: The operator MUST be able to add a persona by adding one data file, with zero edits to skill logic.
F30: Each persona MUST execute as an independent delegated subagent with its own browser session.
F31: Persona subagents MUST execute in parallel as background tasks.
F32: The orchestrator MUST merge all per-persona ledgers into the single JSON findings file.
F33: A No answer to any of the 4 walkthrough questions at a step MUST produce a friction instance for that step.
F34: The persona agent MUST record one friction instance for every ambiguity resolution that the happy-path task list does not require.
F35: The validity-envelope section MUST contain at least these 6 disclosures: not a replacement for real user research, no willingness-to-pay claims, no population-rate claims, no ISO-9241-11 compliance claim, no guarantee that severity values are comparable or reproducible across runs regardless of whether severity_factors is free-text or numeric, cognitive walkthroughs are weaker on standardized well-learned interaction patterns independent of the F27 label. # CR1-20 CR3-12 CR4-M10 CR4-B3
F36: The runner command-line interface MUST conform to the contract recorded in docs/adr/0001-runner-cli-contract.md.
N1: The skill package MUST conform to the Anthropic agent-skills format with a SKILL.md entry file carrying name plus description frontmatter.
N2: The SKILL.md body MUST stay under 500 lines, with personas, schemas, templates in bundled resource files.
N3: The project license MUST be MIT.
N4: A CI run MUST complete headless without interactive operator input.
# N5 provenance: agent-set assumption (2026-07-08), not founder-stated, not brief-sourced; validate empirically during build.
# N5 derivation (CR1-25, corrected CR2-8, reworded CR3-18): under F30/F31 parallel execution, wall-clock
# cost is ~1x a single persona's time, not personas x actions — the original derivation multiplied 3
# personas x 50-action runner cap (F57) x ~18s per-action budget as if sequential. Corrected derivation:
# ONE persona's 50-action runner cap (F57) x ~18s per-action budget (agentic round-trip plus evidence
# capture plus redaction) computes to ~15 minutes of raw per-persona compute; the 45-minute N5 bound
# therefore adds ~3x margin for LLM-latency variance, retries, and CI-runner contention (per N9's
# parallel-derivation rule), not itself empirically derived — the per-action-budget figure remains
# pending empirical measurement at build time. (CR3-18: the prior wording claimed the arithmetic
# "roughly equals" 45 minutes when the actual product is 15 minutes; this restates the real computed
# figure and separates it from the enforced bound. No change to the enforceable N5/N9 requirement lines.)
N5: A 3-persona run against a 5-step task list MUST complete within 45 minutes on one machine. # CR1-25 CR2-8
N6: A run against a localhost target URL MUST succeed without any third-party network service beyond the agent runtime itself.
N7: All shipped artifacts MUST be written in English.
