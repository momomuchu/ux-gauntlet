#### F40's default dry-run boundary makes the spec's own flagship F10/F11/F12/F14 scenario impossible
**IDs:** F40, F7, F10, F11, F12, F14, spec.md:57-65, D14

**Fix directive:** Either rewrite the spec.md scenario at lines 57-65 to explicitly note `--full-submission` is required to observe the dashboard outcome (and add a companion scenario showing the default-mode outcome: task_completed=false, reason_code=dry-run-boundary-stop per F123), or add a 5th D14-family per-step flag (e.g. `audited_terminal_step`) that exempts only the task's own final non-idempotent submission from F40 by default, distinct from `--full-submission`'s run-global scope.

#### "step" is undefined for off-path friction records that the finding_id identity function depends on
**IDs:** F10, F34, F45, F92, F103, D12, requirements.txt:17,73,120
**Failure story:** F10/F34 mandate friction records for actions that by definition aren't happy-path steps, but F45/F92's identity tuple requires `step` to be "the happy-path step index." **Fix directive:** In docs/specs/0001-ux-gauntlet-mvp.spec.md, add to the F45/F92 bullet cluster (near line 183/236) a new atomic requirement, e.g. F143: "For a friction instance whose friction_type is walkthrough_extra_action (F10) or ambiguity_resolution (F34), the `step` field in the F45/F92 identity tuple MUST equal the index of the next not-yet-completed happy-path step at the time the friction occurred, never the index of the last-completed happy-path step." Add the same line (atomic, no and/or compounds) to .swe-spec/requirements.txt after F92 (~line 120), tagged with a DR/CR reference (e.g. "# DR-06a CR2-6 CR3-1"). Add a RED fixture pair to test/fixtures/ (e.g. findings-offpath-step-divergent-detour-ok.json and a -bad.json) modeling two personas taking different off-path detours between the same two happy-path steps (e.g. step 2 pending), asserting both friction records compute `step`=2 (the next-pending step) and collapse to convergence_tier=2/one finding_id under the gate — and a -bad.json where one record wrongly uses the last-completed step index, asserting the gate fails it (or that it fails to merge, dropping expected convergence_tier). Wire this fixture pair into test/acceptance.test.mjs alongside the existing F45/F92/D12 tests (~line 227-237).

#### F41's robots.txt gate has no defined behavior for a missing robots.txt — the most common real localhost case — and the frozen test cannot reach the code path
**IDs:** F41, F42, F80, N8, F107, F108

**Fix directive:** In .swe-spec/requirements.txt, add a new atomic requirement immediately after F42 (e.g. F148, tail-append to avoid renumbering): "F148: When a target's robots.txt is absent (HTTP 404) or returns a non-2xx/non-404 error on an otherwise-reachable target, the runner MUST treat the target as allow-all for robots.txt purposes and proceed with crawling. # DR-04a". Add one acceptance-test case in test/acceptance.test.mjs adjacent to the F41/F42 test (after line 448): a fixture (e.g. test/fixtures/robots-404-allow-all-ok.json) representing a reachable target whose robots.txt fetch 404'd, asserting gate() returns code 0 (not refused) — this closes the coverage hole the port-9 (fully unreachable) pattern leaves open, since that fixture-gate harness is the only mechanism this frozen suite uses to exercise F41/F42 behavior.
