## 2. CONFIRMED defects

### BLOCKER

**B1 — S42 omits the render_environment_id precondition its own governing prose (D5b/SN8) says it has**
IDs: S42, S21, SN8, D5b, S12, S35
S42's literal requirement text (requirements.txt:50, spec.md:218) promises a byte-identical non-axe finding set given only pinned axe-core + browser version — no render_environment_id clause — while S21's sibling text (requirements.txt:28) and spec.md's own D5b/SN8 prose both assert S42 already carries that scoping. It doesn't. A builder implementing S42 literally ships an unscoped determinism claim that SN8's own font-rendering mechanism (OS glyph shaping flipping S12's bounding-box tie-break) can falsify across CI runners with different font stacks, on byte-identical DOM/CSS.
Fix directive: Append the identical clause S21 already carries to S42's requirements.txt line: '...the same pinned browser version, and a matching render_environment_id across runs.' Update spec.md's S42 acceptance-criteria bullet (line 218) to list the same four preconditions S21's bullet (line 214) lists, so the two sibling determinism requirements are textually symmetric, not just symmetric in surrounding prose.

**B2 — S1's settle precondition has no image/background-image decode gate, falsifying S21's byte-identical promise even when render_environment_id matches**
IDs: S1, S21, S5, S18
S1's settle gate (page-load, fonts.ready, 500ms mutation quiescence, animation exhaustion, 10s cap) never observes image/background-image load or decode completion — invisible to the MutationObserver because paint-only changes produce no DOM mutation. axe-core's color-contrast rule (S5) documents returning `incomplete` when it can't resolve a background color synchronously (classic case: undecoded background image behind text). Two runs on the identical DOM, same pinned axe/browser/render_environment_id, both past S1's settle gate, can straddle that image's decode instant and diverge on contrast incomplete-vs-pass, falsifying S21's byte-identical promise via a mechanism unrelated to render_environment_id.
Fix directive: Extend S1's settle precondition with an explicit image-readiness gate: every `<img>` and CSS background-image reachable from the rendered DOM must reach a decoded/complete state (e.g. await Promise.all of img.decode() calls plus a computed-style background-image resolution check) before axe injection, still bounded by the existing fixed 10-second cap (falling into settle-timeout like any other unmet precondition).

## 4. Systemic observations

- **The S24/route-join defect was independently reconfirmed three times from three different lenses (feasibility M3, evidence-fidelity M8, composition M8-dup) with materially the same root cause** (no SPEC 0001 mechanism ever populates `run.route`) and three different, non-identical fix directives. This is the single most over-represented defect in this round — treat it as one systemic gap requiring one coordinated fix (pick option (a) or (b) once), not three independent line edits.
- **Prose vs. requirement-text drift is a recurring pattern, not a one-off**: B1 and B3 are the same underlying defect (S42 missing the render_environment_id clause its own D5b/SN8 narrative claims it has) surfaced twice by independent lenses — the spec's freeform rationale sections (D5b, SN8, Known-gaps) repeatedly assert scoping/behavior that was never actually written into the corresponding S-numbered requirement text. Any future CR4-style "add a clause to S21" edit pass must grep sibling requirements (S21↔S42, S52↔S38/S56) for the same clause before considering the edit complete.
- **The CI-block predicate table's "advisory" half (B7) and its "block" half's field-selection correctness (B6) are the same class of gap**: tests exist only for the BLOCK direction, never proving the gate doesn't over-block, and BLOCK predicates inconsistently read derived fields (severity) vs. raw fields (impact, code) across S38/S52/S56 with no stated rule for which is authoritative. A single systemic fix — mandate all CI-block predicates read raw axe `impact` or the non-axe `code` directly, never a derived `severity` integer, and require both BLOCK and PASS fixtures for every predicate table row — would close B6, B7, and M6 in one requirement-text pass rather than three.
- **Fixture-level test coverage lags requirement text by roughly one CR round across this spec** (M9, M10, M11, M12 are all "requirement exists, fixture/test doesn't exercise its full literal claim"): every CR4-introduced or CR4-edited requirement should ship its acceptance-test coverage in the same commit, not a later round — the recurring pattern of a requirement passing req-lint while its test only exercises half its clause is now the dominant defect class in this round (5 of 12 MAJORs).
- Severity claims in the input attack set were miscalibrated in a consistent direction on evidence-fidelity-lens items: two attacks claimed BLOCKER/MAJOR that verification downgraded to MINOR (Mn1, Mn2) because the underlying tradeoffs were already adjudicated and disclosed elsewhere in scrub-log/spec.md — evidence-fidelity findings should be checked against scrub-log's decision trail before severity is assigned, not just against the literal requirement text.
